# 09. 배포 계획 — 웹 선출시 → 모바일 스토어

## 전략: 웹이 곧 소프트론칭이다

단일 HTML 게임이므로 **웹 배포 = 무료·즉시·전 세계 소프트론칭**. 여기서 리텐션·재미 신호를 확인한 뒤 Unity 모바일 빌드에 투자한다 (04 문서의 "지표 검증 전 큰돈 금지" 원칙의 배포판).

## 1. 웹 배포 (GitHub Pages) — 지금

파이프라인: `prototype-web/` 푸시 → GitHub Actions(`.github/workflows/deploy-pages.yml`) → Pages 자동 배포.

**1회 설정 (저장소 관리자, 1분):**
1. GitHub 저장소 → **Settings → Pages**
2. **Source: GitHub Actions** 선택
3. Actions 탭에서 `Deploy web game to GitHub Pages` 실행 확인
4. 공개 URL: `https://<계정>.github.io/<저장소>/`

**버전 정책**: `vMAJOR.MINOR` — 시스템 추가 = MINOR, 밸런스 리셋급 = MAJOR. 게임 내 타이틀 화면에 버전 표기, 커밋 태그와 일치.

## 2. 출시 품질 체크리스트 (웹 v6 폴리시 패스)

- [ ] 타이틀 화면 (로고 텍스트·버전·이어하기/새 게임)
- [ ] 첫 런 튜토리얼 오버레이 (굴리기 → 전투 → 점령 → 완주 → 하강/귀환, 5단계 코치마크)
- [ ] 사운드: WebAudio 합성 SFX (주사위·타격·크리·획득·레벨업·사망) + 음소거 토글 — 외부 파일 없이
- [ ] 15층 최종 보스 연출 + 엔딩 + **어센션** (클리어 후 난이도+, 수식어 1개씩)
- [ ] 설정: 사운드/연출 속도/데이터 초기화
- [ ] 통계: 총 런·최고 층·처치 수·승률
- [ ] PWA: manifest + service worker + 아이콘 → 폰 홈 화면 설치, 오프라인 플레이
- [ ] 크레딧 + 피드백 링크 (GitHub Issues)
- [ ] 성능: 저가폰 체감 확인 (트윈 과다 금지), 화면 꺼짐 복귀 시 상태 보존

## 3. 공개 후 루프 (주간)

1. 피드백 수집: GitHub Issues + 커뮤니티 (인디 게임 갤러리, r/incremental_games, X/트위터 개발일지)
2. 지표(수동이라도): 방문→첫 런 완료율, 평균 도달 층 분포 — 이후 gtag 삽입 검토
3. 주 1회 밸런스/콘텐츠 패치 (시뮬레이터 검증 후 푸시 = 자동 배포)

## 4. 모바일 스토어 배포 (웹 신호 확인 후)

Unity 프로젝트는 `unity-integration/` + SETUP.md로 준비 완료. 스토어 제출 체크리스트:

**공통**
- [ ] 앱 아이콘(1024px)·스크린샷 5장·소개 GIF (06 문서 AI 아트 파이프라인)
- [ ] 개인정보처리방침 URL (광고 SDK 도입 시 필수) — GitHub Pages에 정적 페이지로
- [ ] 게임 내 라이선스 고지 (CREDITS)

**Google Play**
- [ ] Play Console 앱 생성 → 비공개 테스트 트랙(테스터 12명·14일, 신규 개인 계정 요건)
- [ ] AAB 빌드 (Unity: Android App Bundle 체크), 타겟 API 레벨 최신 요건 확인
- [ ] 데이터 보안 양식, 콘텐츠 등급 설문 (사행성: 게임 내 재화만 — 12세 목표)

**App Store**
- [ ] Xcode 아카이브 (macOS 필요) → TestFlight 내부 테스트
- [ ] App Privacy 항목, 심사 노트에 게임 루프 설명

**출시 순서**: 웹 지표 양호 → Android 비공개 테스트(2주) → 양 스토어 동시 정식 출시 (Apple 계정 보유로 동시 가능, 04 문서).

## 5. 웹 배포의 한계와 다음 단계

- Pages는 정적 호스팅 — 랭킹·클라우드 세이브 없음 (로컬 저장만). 일일 던전 랭킹은 Firebase 붙이는 시점에
- 아티팩트 URL(claude.ai)은 개인 검증용, Pages URL이 공유용 공식 링크
