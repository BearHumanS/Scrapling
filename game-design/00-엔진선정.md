# 00. 게임 엔진 선정

## 결론부터 (1인 개발 확정 기준)

**Unity 6 (2D 프로젝트, URP)** 로 확정합니다.

1인 개발에서 가장 부족한 자원은 시간과 아트입니다. Unity는 이 두 가지를 가장 크게 절약해 줍니다:

- **에셋 스토어가 아티스트를 대체** — SD 캐릭터, 던전 타일, UI 팩을 구매해 초기 아트 비용 0원에 가깝게 시작 가능
- **광고·IAP·분석 SDK가 검증되어 있어** 수익화 연동을 혼자서도 며칠 안에 끝낼 수 있음 (Godot은 이 지점에서 플러그인 품질 편차로 시간을 잃기 쉬움)
- 턴제·보드·인벤토리 등 필요한 모든 시스템의 튜토리얼·유료 템플릿이 존재 → 막혔을 때 혼자 해결하는 속도가 다름

Godot 4는 훌륭한 엔진이지만, "상용 모바일 출시까지 혼자서"라는 조건에서는 광고/IAP/스토어 대응에서 잃는 시간이 라이선스 무료의 이점보다 큽니다. (Unity Personal은 연매출 20만$까지 무료이므로 1인 개발자에게 실질 비용도 0원입니다.)

이 게임(브루마블 × 던전 RPG)은 그래픽 부하가 낮은 2D/2.5D 턴제 게임이라 사실상 어떤 엔진으로도 만들 수 있습니다. 따라서 엔진 선택 기준은 성능이 아니라 **개발 속도, 에셋 생태계, 모바일 배포 경험, 팀 채용**입니다.

### Unity를 추천하는 이유 (이 게임 기준)

1. **턴제/보드/RPG 레퍼런스와 튜토리얼이 가장 많다** — 주사위 물리, 타일맵, 턴제 전투, 인벤토리 등 필요한 모든 시스템의 예제·유료 에셋이 존재
2. **모바일 퍼블리싱 파이프라인 성숙** — IAP, AdMob/Unity Ads, Firebase, GameAnalytics 등 SDK 연동이 검증됨
3. **DOTween, Odin Inspector, Addressables** 등 생산성 도구로 소규모 팀 개발 속도가 빠름
4. **확장성** — 나중에 3D 연출(주사위, 보스 컷신)이나 실시간 멀티(Netcode, Photon)를 붙이기 쉬움
5. 한국 모바일 게임 업계 표준이라 협업자/외주 구하기가 가장 쉬움

### Godot을 선택해도 되는 경우

- 1인 개발 + 취미/인디, 라이선스·계정·설치 용량 부담을 최소화하고 싶을 때
- 2D 전용 기능(타일맵, 씬 트리)이 가볍고 직관적이라 프로토타입 속도는 오히려 빠름
- 약점: 모바일 광고/IAP 플러그인 품질 편차, 콘솔·퍼블리셔 대응 경험 부족

### 탈락 사유

- **Unreal**: 2D 턴제 모바일에 과한 스펙. 빌드 크기·발열·개발 난이도 모두 불리
- **Cocos**: 성능은 좋으나 한국어 자료·인력 풀이 얇음
- **Flutter/Flame**: UI는 강하지만 게임 시스템(물리 주사위, 연출)용 생태계 부족
