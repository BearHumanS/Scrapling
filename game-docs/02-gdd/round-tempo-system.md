## 1. 핵심 규칙 (사용자 제안)

- **1완주 = 1라운드**: 내 보드를 한 바퀴 돌면 라운드 +1.
- **라운드는 유저별 비동기**: 플레이어마다 라운드 수가 다를 수 있음.
- **빨리 돌면 라운드↑**: 완주가 빠를수록 라운드가 높아짐.
- **3라운드마다 타일 강화**: 타일 티어가 올라 **보상↑**.
- **트레이드오프**: 빨리 도는 대신 **초반 파밍이 부족**할 수 있음.

> 한 줄 요약: **"빠르게 돌아 스케일업(티어)할 것인가, 천천히 파밍해 지금 강해질 것인가."**

## 2. 성립 조건 — "속도는 선택이어야 한다"

주사위는 랜덤이라 속도 자체를 직접 통제할 수 없다. 따라서 **매 턴 선택**으로
템포를 만든다. → **핵심 메커니즘: 턴마다 [파밍] vs [전진] 택1.**

### 권장 모델: 턴당 1행동 (파밍 / 전진)
매 턴: 주사위 → 이동 → 도착 타일에서 **하나** 선택.

| 선택 | 효과 | 성향 |
|------|------|------|
| **파밍(개발)** | 현재 타일 **개발도 +1** + 즉시 수확(자원/유닛/트랩) | 느리지만 **지금 강함** |
| **전진(가속)** | 다음 턴 **추가 이동/리롤**(완주 가속), 수확 스킵 | 빠르게 **라운드↑=티어↑** |

- **파밍 위주** → 라운드 적음, **타일 개발도 높음**(초반 경제·수비 강함).
- **전진 위주** → 라운드 많음, **타일 티어 높음**(후반 폭발적), 단 **초반 빈약·취약**.

> 이 한 가지 선택이 사용자가 말한 "빨리 돌면 라운드↑ / 초반 파밍 부족"을
> **플레이어의 능동적 결정**으로 만든다.

## 3. 타일 파워 공식 (티어 × 개발도)

두 축을 곱해 **양쪽 빌드가 모두 유효**하도록 한다.

```
tile_tier(round)   = 1 + floor(round / 3)      # 3라운드마다 +1 (전진형이 유리)
tile_dev(tile)     = 파밍 선택 누적 횟수         # (파밍형이 유리)
tile_output        = BASE * tile_tier * (1 + 0.5 * tile_dev)
```

| 플레이어 | 라운드 | 티어 | 대표 타일 개발도 | 산출(예, BASE=10) |
|----------|:---:|:---:|:---:|:---:|
| **전진형(빠름)** | 9 | 4 | 1 | 10×4×1.5 = **60** (티어로 스케일) |
| **파밍형(느림)** | 4 | 2 | 4 | 10×2×3.0 = **60** (개발로 스케일) |

→ **같은 시점에 다른 경로로 비슷한 파워**. 차이는 **타이밍**: 파밍형은 초반에,
전진형은 후반에 정점. (수치는 [balance-design](balance-design.md)에서 튜닝.)

## 4. 3라운드 강화(티어업)의 의미

- 라운드 3·6·9…에서 **보드 전역 타일 티어 +1** → 이후 수확 보상 급증.
- 전진형은 이 마일스톤을 **먼저** 밟아 스노볼 시동.
- 단, 티어만 높고 개발도가 낮으면 산출이 기대만큼 안 나옴(위 공식) → **무지성 질주 방지**.

## 5. 침공 타이밍 (비동기 라운드에서)

라운드가 유저별로 다르므로, 침공/전투는 **"침공 창(Invasion Window)"** 으로 처리.

- **권장(싱글/턴제)**: 라운드 마일스톤(3·6·9…)마다 **침공 페이즈** 개방 →
  현재 상태의 상대(AI) 보드로 **침공(A형)**. 내가 심은 트랩이 상대 보드에서 발동.
- **능동 개시 옵션**: "공격 개시"로 준비됐을 때 침공(상대는 그 시점 방어 상태).
- **멀티(후속)**: 실시간은 창 동기화, **비동기**는 "상대의 마지막 방어 스냅샷"에 침공.

> 전진형은 침공 창을 빨리 여는 대신 병력·트랩이 얕고, 파밍형은 늦게 열되 탄탄.

## 6. 밸런스 — 스노볼 & 카운터

빠른 스케일이 **일방적 우위**가 되면 안 된다. 안전장치:

1. **초반 취약성**: 전진형은 자원·유닛·트랩이 얇음 → **조기 침공에 약함**(파밍형의 활로).
2. **개발도 게이팅**: 티어가 높아도 개발도 낮으면 산출·방어가 부족(§3 공식).
3. **티어 체감 수익**: 고티어일수록 파밍 비용/시간↑ 또는 티어 계수 완만화.
4. **캐치업**: 뒤처진 쪽에 침공 성공 시 추가 보상(라운드 격차 보정).
5. **트랩 카운터플레이**: 모든 방해에 반격 수단([proposal-dual-board](proposal-dual-board.md) §6).

> 목표 구도(가위바위보): **파밍형=초반 강세 / 전진형=후반 강세 / 균형형=중반**.

## 7. 라운드 진행 예시 (개념 시뮬)

```
전진형 A: 파밍<전진. R3 도달(턴~9)에 티어2, 침공창 開 → 얕은 병력으로 견제
          R6(턴~18) 티어3, R9 티어4 → 후반 폭발
파밍형 B: 파밍>전진. R3 도달(턴~15)이지만 타일 개발도 높아 수비·초반 병력 탄탄
          A의 조기 침공을 막아내면 유리, 장기전은 A가 스케일로 역전 시도
```

## 8. 프로토타입(M0.5) 반영 포인트

"파밍 몇 턴 → 침공 1회" 최소 슬라이스에 본 시스템 축소 적용:
- 턴당 **[파밍]/[전진]** 선택 UI.
- 라운드 카운트(완주 시 +1), **3라운드 티어업** 데모.
- `tile_output = BASE * tier * (1+0.5*dev)` 적용.
- 라운드 3에서 **AI 보드 침공(트랩 1~2종)** → 승패 → 재미 게이트.
