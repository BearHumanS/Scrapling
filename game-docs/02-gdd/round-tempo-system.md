## 1. 핵심 규칙 (사용자 제안)

- **1완주 = 1라운드**: 내 보드를 한 바퀴 돌면 라운드 +1.
- **라운드는 유저별 비동기**: 플레이어마다 라운드 수가 다를 수 있음.
- **완주 속도 = 순수 주사위 운**: 빨리 도는 건 운이지 실력·선택이 아니다.
- **3라운드마다 타일 강화**: 타일 티어가 올라 수확 보상↑.
- **"빨라도 좋은 게 아님"**: 빨리 돌면 라운드/티어는 빨리 오르지만, 그만큼
  **초반 파밍(축적)이 얇아** 취약해진다 → 유·불리가 상쇄되는 **양날의 변동성**.

> 한 줄: **"주사위 운으로 템포가 갈릴 뿐, 빠름=승리가 아니다. 전략은 다른 데 있다."**

## 2. 속도는 운이다 — 전략은 어디에 있나

완주 속도 자체는 통제 불가(주사위). 플레이어가 실제로 **결정하는 것**은:

1. **자원 배분** — 수확한 자원을 어떤 타일 개발/유닛/장비/트랩에 투자할지.
2. **건설·개발 우선순위** — 어떤 칸을 키우고 무엇을 남길지.
3. **수비 설계** — 트랩·수비 유닛 배치(침공 대비).
4. **침공 타이밍** — 언제 상대 보드로 쳐들어갈지.
5. **변동성 대응** — 이번 런의 주사위 흐름(빠름/느림)에 맞춰 전략 조정.

> 즉 라운드/템포는 **로그라이트식 "운의 레이어"**(예: Loop Hero의 드로우)이고,
> 플레이어는 그 위에서 빌드를 운영한다.

## 3. 파밍 모델 (핵심 — 확인 필요)

"빨라도 좋지 않다"가 성립하려면 파밍이 이동과 어떻게 엮이는지가 관건이다.
두 후보를 두고 **권장안 + 대안**으로 정리한다. (프로토타입에서 최종 검증.)

### 권장안: 착지 수확 + 시간 축적(상한)
- 각 칸은 매 턴 자원을 조금씩 **축적**(개발도·티어에 비례), **상한(cap)** 존재.
- 매 턴 **착지한 1칸**에서 축적분을 **수거** + 그 칸 **개발도 +1**.
- **빠른 완주(고롤)**: 칸을 자주 밟아 **자주·소량 수거**(축적할 틈이 적음) →
  라운드/티어는 빨리 오르나 **총 축적·개발 얇음** → 초반 취약.
- **느린 완주(저롤)**: 같은 칸을 뜸하게 밟되 **크게 수거**(많이 쌓임) →
  개발·수비 탄탄, 티어는 늦게.
- 결과: 총량이 대략 상쇄 → **속도는 유·불리 중립에 가깝고**, 방치 칸은 상한 초과로 낭비.

### 대안: 착지 칸만 즉시 수확(축적 없음)
- 매 턴 착지 1칸만 정액 수확. 단순하지만 "빠름=티어만 빨리"라 **빠름이 유리해지기 쉬움**
  → 이 경우 §5의 **초반 취약** 페널티로 균형을 강하게 잡아야 함.

> **결정 필요**: 권장안(시간 축적+상한) vs 대안(즉시 수확). 기본은 **권장안** 가정.

## 4. 타일 티어 & 개발도

```
tile_tier(round) = 1 + floor(round / 3)     # 3라운드마다 +1 (운 좋아 빨리 돌면 먼저 도달)
tile_dev(tile)   = 그 칸에 착지한 누적 횟수  # (자주 밟힌 칸일수록 성장 — 이것도 운의 결과)
tile_yield       = BASE * tile_tier * (1 + K * tile_dev)   # K는 튜닝값(예 0.5)
```

- **티어**: 라운드로 오름 → 운으로 빨리 도는 쪽이 먼저 도달(=잠재력).
- **개발도**: 어디에 착지하는지의 누적 → **이것도 선택이 아니라 주사위 분포의 결과**.
- 빠른 쪽은 **티어↑ 개발↓**(잠재력만 큼), 느린 쪽은 **티어↓ 개발↑**(실현치 큼).

## 5. "빨라도 안 좋은" 이유 (밸런스 축)

빠른 완주가 **일방적 이득이 되지 않도록** 하는 장치. (사용자 정정 반영.)

1. **초반 취약(핵심)**: 빨리 도는 쪽은 축적·개발·수비가 얇음 → **상대의 조기 침공에 무방비**.
   ("초반 파밍을 많이 못 한다"의 직접적 결과.)
2. **티어-개발 괴리**: 티어만 높고 개발이 낮으면 수확/방어가 기대만큼 안 나옴(§4 공식).
3. **축적 상한 낭비**: (권장안) 자주 못 들른 칸은 상한 초과분 소멸 → 빠름의 잦은 방문이 항상 이득은 아님.
4. **캐치업**: 뒤처진 쪽이 침공 성공 시 라운드 격차 보정 보상.

> 목표 구도: **빠름 = 후반 잠재력(고티어)이지만 초반 도박 / 느림 = 초반 견실(고개발·수비)**.
> 어느 쪽도 지배 전략이 아니게 튜닝.

## 6. 침공 타이밍 (비동기 라운드)

- **권장(싱글/턴제)**: 라운드 마일스톤(3·6·9…)마다 **침공 창** 개방 → 현재 상태의
  상대(AI) 보드로 **침공(A형)**, 내가 심은 트랩이 상대 보드에서 발동.
- **능동 개시 옵션**: 준비되면 "공격 개시"로 침공(상대는 그 시점 방어 상태).
- **멀티(후속)**: 실시간=창 동기화 / 비동기=상대의 마지막 방어 스냅샷에 침공.

## 7. 진행 예시 (개념)

```
운 좋아 빠른 A: 라운드가 빨리 쌓여 티어↑ 선점. 그러나 축적·수비 얇음
              → B가 조기 침공하면 위험. 버티면 후반 고티어로 스노볼 시도.
운 나빠 느린 B: 티어는 늦지만 개발도·수비 탄탄, 자원 축적 큼
              → 초반 주도권. A의 후반 스케일 전에 끝내려 함.
```
→ 속도는 운, 승패는 **그 운을 어떻게 운영/침공했는가**로 갈린다.

## 8. 프로토타입(M0.5) 반영 포인트

"파밍 몇 턴 → 침공 1회" 최소 슬라이스:
- 주사위 이동(선택 없음), 착지 칸 수확(권장안: 축적+상한 or 대안: 즉시).
- 라운드 카운트(완주 +1), **3라운드 티어업** 데모.
- `tile_yield = BASE * tier * (1 + K*dev)` 적용.
- 라운드 3에서 **AI 보드 침공(트랩 1~2종)**, **초반 취약** 페널티가 실제로 느껴지는지 확인.
