## 1. 목적

문서(기획)에서 **첫 코드(Godot 프로토타입)** 로 넘어가기 위한 다리.
M0 프로토타입의 **정확한 범위·폴더 구조·작업 순서·완료 기준**을 못박아,
스코프 크리프 없이 "코어 루프가 재미있는가?"만 검증한다([roadmap](../05-production/roadmap.md) M0).

## 2. 단 하나의 검증 질문

> **"주사위 굴림 → 이동 → 칸 이벤트 → (구매/전투) → 정산"의 한 바퀴가
> 손맛 있게 돌아가는가?"**

이 질문에 답하는 데 필요 없는 것은 전부 **범위 밖**.

## 3. 범위 (Scope)

### In (M0에 반드시)
- 회색박스 보드 1개(약 12~16칸 순환, 칸 데이터 기반)
- 주사위 굴림 → 말 이동(애니메이션은 단순) → 도착 칸 이벤트
- 칸 종류 최소셋: **출발 / 땅(구매·통행료) / 전투 / 보물 / 빈칸**
- 골드 자산 + 땅 구매/통행료(부루마블 코어)
- **턴제 전투 1종**(플레이어 1 vs 적 1, 공격/스킬1/방어), 슬라임 1종
- 캐릭터 1클래스(전사) 고정, 기본 스탯/HP
- AI 또는 더미 상대 1명(턴 교대 검증용, 휴리스틱 최소)
- 게임 종료 조건 1개(예: N바퀴 후 자산 비교 or 보스 더미 격파)
- 디버그 표시(상태/로그)

### Out (M0에서 제외)
- 로그라이트/캠페인 구조, 스토리/이벤트 스크립트, 메타 성장
- 스킬 트리, 장비/인벤토리, 다중 클래스, 상점 UI
- 도트 아트/사운드 완성(플레이스홀더만), 현지화
- 멀티플레이, 세이브/로드(메모리상만), 밸런스 튜닝

> M0는 "재미 검증"이 목적이지 완성도가 아니다. 통과 후 M1에서 살붙임.

## 4. 빌드할 슬라이스(우선순위 순)

```
1) 보드 데이터 + 칸 배치 렌더(회색박스)
2) 주사위 굴림 → 말 이동 → 도착 칸 식별
3) 턴 상태기계(주사위→이동→칸처리→행동→턴종료→다음)
4) 땅 구매 / 통행료(골드 자산)
5) 전투 씬(턴제 1:1) 진입·복귀
6) 더미 상대(AI) 턴 교대
7) 종료 조건 + 결과 화면
8) 디버그/치트(스킵·골드 추가) — 테스트 가속
```

## 5. 폴더 구조 (M0)

> [architecture](architecture.md) §8 구조의 축소판. 게임은 **별도 디렉터리**
> `game-prototype/`(또는 별도 repo)에 둔다. Scrapling 라이브러리와 섞지 않는다.

```
game-prototype/
├── project.godot
├── autoload/
│   ├── GameState.gd        # 자산·턴·플레이어 상태(메모리)
│   ├── EventBus.gd         # 시그널 허브
│   └── RNG.gd              # 시드 난수
├── scenes/
│   ├── Main.tscn/.gd       # 부트스트랩
│   ├── Board.tscn/.gd      # 보드·칸·말·HUD
│   └── Combat.tscn/.gd     # 전투
├── scripts/
│   ├── TurnStateMachine.gd # 턴 진행
│   └── AIController.gd      # 더미 상대
├── data/
│   ├── board_proto.tres    # 칸 배열
│   └── enemy_slime.tres    # 적 1종
└── assets/placeholder/     # 회색박스 스프라이트
```

## 7. 기술 메모

- **Godot 버전 고정**: [tech-stack](tech-stack.md) 결정값 사용(미정 시 최신 안정 4.x).
- **언어**: GDScript(프로토 속도 우선).
- **상태기계/데이터주도/결정적 RNG** 원칙은 M0부터 가볍게 적용([architecture](architecture.md)).
- 애드온(GodotSteam 등) **불필요** — M0 제외.

## 8. 완료 기준 (Definition of Done)

- [ ] 한 판이 처음~끝까지 끊김 없이 플레이된다(주사위→…→종료).
- [ ] 땅 구매·통행료로 골드가 의미 있게 변동한다.
- [ ] 전투 진입→승패→보드 복귀가 동작한다.
- [ ] 더미 상대와 턴이 교대된다.
- [ ] 내부 플레이로 "코어 재미" 정성 평가를 받았다(게이트).

## 9. 검증 방법 (이 환경 제약)

- 본 클라우드 환경에서는 **Godot 에디터 실행/렌더 검증 불가** → 스캐폴딩은
  텍스트 파일로 생성하고, 실제 실행·확인은 **로컬 Godot 에디터**에서 수행.
- 가능 시 핵심 로직(피해·경제·턴 전이)은 **GUT 단위 테스트**로 헤드리스 검증.
- 체크리스트(§8)를 로컬 플레이로 1개씩 확인.
